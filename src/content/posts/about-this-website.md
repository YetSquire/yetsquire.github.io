<div><p class="c2"><span class="c9"></span></p></div><p class="c14 title" id="h.bjucoqnl1emo"><span class="c11">Title: About This Website</span></p><p class="c0 subtitle" id="h.9rn6bppeqmqx"><span class="c7 c12">Date: 05/06/2026&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;</span></p><p class="c0 subtitle" id="h.ogvz1z6991io"><span class="c7">Tags: Featured, Thought, Project</span></p><p class="c2"><span class="c4"></span></p><p class="c5"><span class="c4">This post aims to answer two questions: </span></p><ul class="c8 lst-kix_eqqlf0v09zrj-0 start"><li class="c3 li-bullet-0"><span class="c4">Why I created this website in its present form</span></li><li class="c3 li-bullet-0"><span class="c4">How this website (and associated components) were built</span></li></ul><p class="c2"><span class="c4"></span></p><h2 class="c1" id="h.hkskd7obcy0o"><span class="c10">Why a website?</span></h2><p class="c5"><span class="c4">A lot of devs, in my opinion, throw up a website as what is essentially a prettier version of a resume. I explicitly think that those kinds of websites don&rsquo;t mean much, with website templates and AI making the creation of good sites not a great indicator of technical talent. </span></p><p class="c2"><span class="c4"></span></p><p class="c5"><span>Rather, I believe that there&rsquo;s a lot a LinkedIn crawl or resume overview doesn&rsquo;t tell you about a person. This website, above everything, is meant to provide context about who I am and what I do. I&rsquo;m not much of a social media guy, so consolidating my thoughts onto one platform will be, I hope, &nbsp;useful for anyone curious about me. </span></p><p class="c2"><span class="c4"></span></p><p class="c2"><span class="c4"></span></p><h2 class="c1" id="h.dqiy1aeaewa3"><span>How&rsquo;d I build this site?</span></h2><p class="c5"><span>First, we should answer a question&ndash; why build a site like this at all? Why not use</span><span class="c16">&nbsp;Substack or Medium or some other platform</span><span>, and just spit out ideas?</span></p><p class="c2"><span class="c4"></span></p><ol class="c8 lst-kix_l3kig0ja660k-0 start" start="1"><li class="c3 li-bullet-0"><span class="c16">I wanted to create a flow that allowed me to directly write from </span><span>a </span><span class="c4">Google Docs as &ldquo;source material&rdquo;. I made a companion extension that propagates changes from a master doc to this website, which makes my specific workflow of editing and publishing easy</span></li></ol><p class="c2"><span class="c4"></span></p><ol class="c8 lst-kix_l3kig0ja660k-0" start="2"><li class="c3 li-bullet-0"><span class="c4">&nbsp;I wanted to build a software product that I myself use, to give myself the experience of maintaining a long-term tool.</span></li></ol><p class="c2"><span class="c4"></span></p><ol class="c8 lst-kix_l3kig0ja660k-0" start="3"><li class="c3 li-bullet-0"><span>I felt like it. </span><span class="c4">I see this website as an application of both my interests in the humanities and software engineering. I hope you enjoy exploring it as much as I enjoyed creating it. </span></li></ol><p class="c2"><span class="c4"></span></p><p class="c5"><span class="c4">Now, let&rsquo;s get into the technical bits:</span></p><ul class="c8 lst-kix_icsvredhg77e-0 start"><li class="c3 li-bullet-0"><span>I built this website on the Astro framework. This was largely because I wanted to compare it to </span><span>Next.js</span><span class="c4">&nbsp;(which I&rsquo;m more familiar with), and because Astro is explicitly better at building websites that are as JS-light as this project was going to be. It ended up being a good choice&ndash; the only page that really used JS was the homepage, which I could hydrate specifically.</span></li><li class="c3 li-bullet-0"><span class="c4">I only use HTML + CSS + JS, no React. There was honestly no need. </span></li><li class="c3 li-bullet-0"><span class="c4">From the beginning, I knew that there were going to be three main components of my writing process&ndash; drafting on Google Docs, previewing locally, and deploying the site properly. The site itself handles the latter two steps, but the Docs -&gt; Local Preview pipeline is handled via a Chrome extension and lightweight local server that runs along with local dev launch. This is the only </span></li><li class="c3 li-bullet-0"><span>I hosted the site on Cloudflare pages. Pretty default, wasn&rsquo;t going to rock the boat there. </span></li></ul><p class="c5"><span style="overflow: hidden; display: inline-block; margin: 0.00px 0.00px; border: 0.00px solid #000000; transform: rotate(0.00rad) translateZ(0px); -webkit-transform: rotate(0.00rad) translateZ(0px); width: 624.00px; height: 468.00px;"><img class="doc-image" alt="" src="/images/posts/about-this-website/img-5d9d847fa03e.png" style="width: 624.00px; height: 468.00px; margin-left: 0.00px; margin-top: 0.00px; transform: rotate(0.00rad) translateZ(0px); -webkit-transform: rotate(0.00rad) translateZ(0px);" title=""></span></p><p class="c13"><span class="c4">Diagram of website flow</span></p><p class="c2"><span class="c4"></span></p><p class="c5"><span class="c4">In all honesty, most of this project was fairly boilerplate. The tagging + sorting system is particularly inefficient because it&rsquo;s a straight linear sort for each combination of tags, and the changing text component is a simple JS script. In practice, the only interesting component is the extension and local server. </span></p><p class="c2"><span class="c4"></span></p><p class="c5"><span class="c4">The extension does almost no work itself. It just detects the current Google Doc and active tab, then POSTs docId and tabId to. The compiler server does the real work.</span></p><p class="c2"><span class="c4"></span></p><p class="c5"><span class="c4">&nbsp; What content.js does:</span></p><ul class="c8 lst-kix_84vijb9nx974-0 start"><li class="c3 li-bullet-0"><span class="c4">checks the Google Doc title with document.title</span></li><li class="c3 li-bullet-0"><span class="c4">renders a floating Compile Tab button</span></li><li class="c3 li-bullet-0"><span class="c4">on click, sends metadata to the server</span></li></ul><p class="c5"><span style="overflow: hidden; display: inline-block; margin: 0.00px 0.00px; border: 0.00px solid #000000; transform: rotate(0.00rad) translateZ(0px); -webkit-transform: rotate(0.00rad) translateZ(0px); width: 624.00px; height: 280.00px;"><img class="doc-image" alt="" src="/images/posts/about-this-website/img-afb917a1d498.png" style="width: 624.00px; height: 280.00px; margin-left: 0.00px; margin-top: 0.00px; transform: rotate(0.00rad) translateZ(0px); -webkit-transform: rotate(0.00rad) translateZ(0px);" title=""></span></p><p class="c5"><span class="c4">The compiler is an Express server in compiler/server.js. In dev it is started by the root npm run dev script in package.json, alongside astro dev.</span></p><p class="c2"><span class="c4"></span></p><p class="c5"><span class="c4">&nbsp; It exposes a series of localhost endpoints for the Chrome extension and authentication process (server can read the Google Doc, but not edit it).</span></p><p class="c2"><span class="c4"></span></p><p class="c5"><span class="c4">&nbsp; The compile path is:</span></p><ol class="c8 lst-kix_rlbywhp987kq-0 start" start="1"><li class="c3 li-bullet-0"><span class="c4">Extension sends docId and tabId</span></li><li class="c3 li-bullet-0"><span class="c4">Compiler fetches full doc structure from Google Docs API </span></li><li class="c3 li-bullet-0"><span class="c4">Compiler extracts metadata from tab plain text</span></li><li class="c3 li-bullet-0"><span class="c4">Compiler renders HTML for the tab body (Google API command)</span></li><li class="c3 li-bullet-0"><span class="c4">Compiler downloads/relinks images</span></li><li class="c3 li-bullet-0"><span class="c4">Compiler cleans exported metadata from the body</span></li><li class="c3 li-bullet-0"><span class="c4">Compiler converts HTML into markdown with frontmatter </span></li><li class="c3 li-bullet-0"><span class="c4">Astro reloads and serves/builds from those generated files</span></li></ol><p class="c2"><span class="c4"></span></p><p class="c5"><span class="c4">I&rsquo;d say the biggest lesson learned through this entire process is to not duplicate work. A lot of effort is put into relatively &lsquo;hidden&rsquo; systems that you can 100% leverage if you ever want to customize a workflow or build out a tool. There&rsquo;s no reason to define a new Doc to HTML pipeline when one exists, nor is there a reason to say, make text editing software when Google Docs is what I&rsquo;d prefer regardless. On the other hand, it&rsquo;s 100% necessary to build out certain tools if the equivalent doesn&rsquo;t exist and you need it badly enough&ndash; i.e. this website. </span></p><div><p class="c2"><span class="c9"></span></p></div>
